Every program for your Dörries is currently keyed in at the Siemens 840D. That works for simple turned shapes, but it puts a ceiling on what the machine can take on, and that ceiling starts to bite as the Penrose workshop grows and new technicians come onto the machine. Here's how I'd suggest moving the programming into Fusion: a post processor proven on your machine, and up to four of your people trained to drive it, in one week on site.

1Where programming at the control holds you back

Conversational programming is fine for a straightforward turned shape. Gas turbine components are rarely that straightforward. They turn up with tapers, blend radii and arcs meeting at points the drawing doesn't always dimension. Each of those has to be worked out by hand before it can be keyed in, and every hand calculation is a chance to get it wrong on a part that's expensive to scrap.

Tool nose radius compensation is the other one. Getting it right on tapers, chamfers and radii is fiddly at the control, and when it's wrong the part is wrong, usually found at inspection rather than before the cut.

While someone's building a program at the control, the table isn't turning. On a machine this size, that's expensive time to have it sitting still.

And the knowledge sits with whoever does the programming. That includes the speeds and feeds that actually work on each material and insert, which live in that person's head or hard coded into whatever program is left on the control from last time. As new technicians come onto the machine, that's a bottleneck, and a real risk when that person is away.

None of that is a criticism of the people doing it now. At the control, there isn't really another way.

2What changes with Fusion

You program from a model of the part. If the part only exists as a drawing, which is common with repair work, you model the profile first, and every point the toolpath needs comes straight off the geometry. The hand calculations go away.

Compensation becomes something you can see. You pick the insert and its orientation from the tool library, and the simulation shows the actual nose shape following the profile, with the stock coming away as it would on the machine. If something's not right, you see it on screen before anything goes near the table.

Programming happens at a desk while the Dörries is cutting the previous job, and the C axis comes along too, so hole patterns and milled features get programmed in the same place as the turning.

The tool library is where the speeds and feeds end up living. Once a cutting strategy for a material or insert is proven, it goes in against that tool, and every program built from it starts from a value someone already knows works. Templates do the same for setups and toolpath sequences you repeat across similar parts. Programming most of a new part becomes picking the template and adjusting it, and the hard thinking happens once, when the template is built.

All of that only counts if the code coming out of Fusion is code your 840D is happy with, which is the post processor's job. That's why we'll prove the post on your machine during the week, with changes made on the spot.

3Before I arrive

Post processor preparation

I'll start from Autodesk's Siemens post and set it up for your Dörries as an X, Z and C axis turn-mill: diameter programming, constant surface speed with a spindle speed cap on every tool, the tool call format your control expects, safe retracts that lift the ram clear before moving across, switching the table between turning and C axis milling, and the program header.

I'll work from whatever documentation exists for the retrofit, paper or digital, plus a few programs that already run on the machine. If no documentation exists, I'll need to talk directly to whoever did the retrofit.

The post is supplied unencrypted and version controlled via GitHub, so you can see exactly what changed between revisions and roll back if you need to.

4The week on site

Five days at Penrose, Monday to Friday, starting around 9am. I'll fly up from Christchurch early Monday morning to be there for the start.

The time is split between training and proving the post at the machine, with the trainees alongside. Seeing their own programs run is half the lesson. Training covers modelling turned profiles from drawings, setups, turning toolpaths, tool nose compensation, and milling with the C axis. We finish by programming two or three of your own parts end to end, running them where time allows.

Nobody becomes a CAM programmer in a week, and I won't pretend otherwise. What your staff will have is a working method for taking a part from drawing to proven program, a post they can trust, and a follow-up day for whatever turns up once they're on their own.

Later: a model of the machine

Fusion doesn't yet support machine simulation for lathes. When it does, a model of your Dörries means you can check clearances around the ram and table before you cut. A machine this age is unlikely to have a 3D model on file, but it's worth asking Starrag now for one, or for general arrangement drawings with the main dimensions of the table, ram and cross rail. From those I can build a simplified model ready for when Fusion supports it, and I'll quote that work at the time.
